1. Visão Geral do Sistema

O Jarvis é um gerenciador de tarefas full stack com controle de tempo, autenticação por usuário, dashboard analítico e timer em modo Picture-in-Picture. O sistema roda inteiramente de forma local, com persistência em SQLite.

O que o usuário pode fazer

  • Criar conta e fazer login
  • Criar, editar e excluir tarefas
  • Organizar tarefas por categoria (Trabalho / Pessoal)
  • Iniciar, pausar e concluir cronômetro regressivo
  • Visualizar timer fora do browser (PiP)
  • Ver dashboard com métricas e gráficos
  • Filtrar tarefas por status e buscar por texto
  • Alternar entre tema claro e escuro

Tecnologias utilizadas

  • Vite — bundler do frontend
  • React 18 — interface do usuário
  • React Router v6 — navegação entre páginas
  • Tailwind CSS v3 — estilização
  • Recharts — gráficos no dashboard
  • Axios — requisições HTTP
  • Express — servidor HTTP
  • better-sqlite3 — banco de dados
  • JWT + bcryptjs — autenticação
  • Document PiP API — timer flutuante

4. Banco de Dados (SQLite)

O banco de dados é um arquivo único server/tasks.db criado automaticamente na primeira execução. Não há configuração adicional necessária.

4.1 Tabela: users

4.2 Tabela: tasks

ColunaTipoDescrição
idINTEGER PKIdentificador único auto-incrementado
user_idINTEGER FKReferência ao dono da tarefa (users.id)
titleTEXTTítulo da tarefa
descriptionTEXTDescrição detalhada (opcional)
categoryTEXTCategoria: 'trabalho' ou 'pessoal'
statusTEXT'nao_iniciada' | 'em_andamento' | 'concluida'
estimated_timeINTEGERTempo estimado em segundos (padrão: 5400 = 1h30)
real_timeINTEGERTempo acumulado em segundos (atualizado ao pausar)
timer_activeINTEGER0 = parado, 1 = rodando
timer_started_atINTEGERUnix timestamp de quando o timer foi iniciado pela última vez
created_atINTEGERUnix timestamp de criação da tarefa
finished_atINTEGERUnix timestamp de conclusão (null até ser concluída)
Como o timer persiste no reload? O tempo restante é sempre calculado em tempo real: restante = estimated_time - real_time - (agora - timer_started_at). Ao recarregar a página, o frontend busca a tarefa do banco, encontra timer_active = 1 e timer_started_at preenchido, e reconstrói o cronômetro corretamente.

6.4 Hook useTimer

Arquivo: src/hooks/useTimer.js

Este hook é a peça central do cronômetro. Ele não armazena estado próprio de quanto tempo passou — calcula isso dinamicamente a cada segundo com base nos dados do banco:

function calcRemaining(task) {
  const now = Math.floor(Date.now() / 1000);  // timestamp atual em segundos
  if (task.timer_active && task.timer_started_at) {
    const elapsed = now - task.timer_started_at;
    return Math.max(0, task.estimated_time - task.real_time - elapsed);
  }
  return Math.max(0, task.estimated_time - task.real_time);
}

Isso garante que o timer seja correto mesmo após um reload da página, sem precisar de WebSocket ou polling.

7. Timer e Picture-in-Picture

7.1 Como funciona o bubble flutuante

O FloatingTimer.jsx é renderizado dentro do Layout e usa o ActiveTimerContext para saber se há uma tarefa com timer ativo. Quando existe, ele aparece como um círculo arrastável com:

  • Anel SVG de progresso (azul → laranja → vermelho conforme o tempo passa)
  • Tempo restante no centro em fonte monospace
  • Hover: botões de pausar e concluir
  • Hover: ícone de pop-out no canto superior direito

O bubble usa eventos de mouse nativos (sem biblioteca) para o drag, calculando o deslocamento a partir da posição inicial do clique.

7.2 Document Picture-in-Picture API

Ao clicar no ícone de pop-out, o código chama:

const pip = await window.documentPictureInPicture.requestWindow({
  width: 260, height: 240
});

Isso abre uma janela nativa do OS gerenciada pelo Chrome/Edge. Em seguida:

  1. Todos os <style> e <link> CSS são copiados para o documento da janela PiP
  2. Um div container é criado no body da janela PiP
  3. O componente PipContent é renderizado dentro desse container via ReactDOM.createPortal
  4. O portal é parte da mesma árvore React, então o timer continua atualizando normalmente
Compatibilidade do PiP A Document Picture-in-Picture API só funciona no Chrome 116+ e Edge 116+. Em Firefox e Safari, ao clicar no pop-out aparece um alert informando. O bubble normal continua funcionando em todos os browsers.

7.3 Onde alterar o tamanho e aparência da janela PiP

Em src/components/FloatingTimer.jsx, procure a função togglePip:

const pip = await window.documentPictureInPicture.requestWindow({
  width: 260,   // ← largura em pixels
  height: 240,  // ← altura em pixels
});

O conteúdo visual da janela PiP está no componente PipContent (mesma função, no topo do arquivo), usando estilos inline para garantir compatibilidade com o documento separado da janela.

8.4 Como adicionar uma nova categoria

As categorias são definidas em dois lugares. Para adicionar, por exemplo, 'estudos':

  1. Em src/components/TaskModal.jsx → array CATEGORIES, adicione { value: 'estudos', label: 'Estudos' }
  2. Em src/components/TaskCard.jsx → objeto CATEGORY_STYLE, adicione a classe de cor para a nova categoria
  3. Em src/components/Sidebar.jsx → array links, adicione o link de navegação

9.4 Segurança em produção

Antes de colocar em produção 1) Troque o JWT_SECRET no arquivo server/.env por uma string longa e aleatória.
2) Configure HTTPS.
3) Ajuste o CORS em server/index.js para aceitar apenas o domínio real.
4) Faça backup periódico do arquivo server/tasks.db.
